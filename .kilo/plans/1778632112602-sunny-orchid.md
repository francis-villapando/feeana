# Course Management Hub — Design Analysis & Proposal

## Current Implementation

**Database Schema:**
- `courses` — id, code, title, archived
- `topics` — id, course_id (FK), title, archived
- `ilos` — id, course_id (FK), topic_id (FK), statement, bloom_level, archived
- `activity_log` — entity, entity_id, action, label, user_id, timestamp

**UI Components:**
- `CourseManagementHub.tsx` — Tabbed interface (Courses / Topics / ILOs) with flat lists
- `EntityFormDialog.tsx` — Unified CRUD form with dynamic fields
- `ActivityFeed.tsx` + `ActivityFeedDialog.tsx` — Recent changes feed
- State managed via `courseStore.tsx` (Zustand-like context) + `courseService.ts` (Supabase)

---

## Identified Issues

### 1. Referential Integrity Drift
- `ilos` stores both `course_id` and `topic_id`. If a topic is reassigned to a different course (`updateTopic` changes `course_id`), all associated ILOs become inconsistent (course_id ≠ topic's course_id).
- No database constraint to ensure `ilos(course_id)` matches `topics.course_id` for the linked topic.

### 2. Duplicate ILO Detection & Uniqueness
- No uniqueness constraint on ILO statements within a course/topic.
- Faculty can accidentally create identical ILOs; hard to identify duplicates across the system.
- No search/filter by Bloom level to group similar outcomes.

### 3. Poor Relationship Visibility
- ILO tab displays only bloom level + statement; **course and topic context is hidden** unless editing.
- Topic rows show only course code — no count of associated ILOs.
- No hierarchical view: cannot see Course → Topic → ILO tree at a glance.
- No visual grouping or nesting, making it difficult to understand structure at scale.

### 4. Limited Filtering & Search
- Global search matches only text (code/title/statement) with no facet filters:
  - Filter ILOs by course or topic
  - Filter by Bloom level
  - Filter by archived status per entity
- Cannot answer questions like "Which ILOs belong to CSEG2?" without manual scanning.

### 5. Scalability & Performance
- All entities loaded into client-side arrays; pagination or virtualization absent.
- Filtering runs on full in-memory arrays — acceptable for small data but degrades with hundreds of ILOs.
- No server-side filtering or indexing strategy visible.

### 6. Missing ILO Metadata
- ILOs have no code (like courses), only a statement. Hard to reference ILOs in discussions, rubrics, or sessions.
- `created_at` not exposed in TypeScript types; cannot sort chronologically.
- No tagging, categorization, or notes.

### 7. Activity Feed Insufficiency
- Activity labels are generic (e.g., "ILO — 'Apply…'"), do not show parent course/topic.
- No filtering by entity type, user, or date range.
- No ability to see changes on a specific course, topic, or ILO.

### 8. Edit Workflow Friction
- Editing an ILO requires selecting course and topic again even if unchanged.
- No bulk operations (archive multiple ILOs, reassign topics).
- No "merge duplicates" or "prevent duplicates" workflow.

## Proposed Design Update

### A. Database Schema Changes

```sql
-- 1. Add unique constraint to prevent exact duplicate ILO statements within same course
CREATE UNIQUE INDEX idx_ilos_unique_statement_per_course
  ON ilos(course_id, lower(statement))
  WHERE NOT archived;

-- 2. Add ILO code field for easy referencing
ALTER TABLE ilos ADD COLUMN code text;
CREATE INDEX idx_ilos_code ON ilos(code);

-- 3. Add generated/topic_id check constraint to ensure consistent course reference
ALTER TABLE ilos ADD CONSTRAINT ilos_course_topic_consistency
  CHECK (course_id = (SELECT course_id FROM topics WHERE id = topic_id));

-- 4. Add indexes for filtering
CREATE INDEX idx_ilos_bloom_level ON ilos(bloom_level);
CREATE INDEX idx_ilos_topic ON ilos(topic_id);

-- 5. Consider adding tags or categories later if needed
```

### B. Updated Data Models

```typescript
// types.ts — extend ILO
export interface ILO {
  id: string;
  courseId: string;
  topicId: string;
  statement: string;
  code: string;           // auto-generated like "CS101-ILO-001"
  bloomLevel: BloomLevel;
  tags?: string[];        // optional, for categorization
  archived: boolean;
  createdAt: string;      // explicit timestamp
}

// Enhanced activity entry with entity snapshot
export interface ActivityEntry {
  id: string;
  entity: EntityKind;
  entityId: string;
  action: ActivityAction;
  label: string;
  timestamp: string;
  userId?: string;
  userName?: string;
  metadata?: {
    courseId?: string;
    topicId?: string;
    changes?: Record<string, { old: unknown; new: unknown }>;
  };
}
```

### C. UI Redesign Using shadcn/ui Components

#### 1. Hierarchical Data Table with Columns & Filters

Replace tabbed lists with a **single unified table** using `@tanstack/react-table` (already present via deps) + shadcn's `DataTable` component pattern:

```tsx
// components/dashboard/CourseHierarchyTable.tsx — new
import {
  ColumnDef,
  flexRender,
  getCoreRowModel,
  useReactTable,
} from "@tanstack/react-table";
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card";
import { Input } from "@/components/ui/input";
import { Button } from "@/components/ui/button";
import { Badge } from "@/components/ui/badge";
import {
  Select,
  SelectContent,
  SelectItem,
  SelectTrigger,
  SelectValue,
} from "@/components/ui/select";
import { Separator } from "@/components/ui/separator";
import { ChevronRight, BookOpen, ListChecks, Target } from "lucide-react";

// Entity type discriminator: "course" | "topic" | "ilo"
type HierarchyRow = CourseRow | TopicRow | ILORow;

interface CourseRow {
  type: "course";
  id: string;
  code: string;
  title: string;
  archived: boolean;
  topicCount: number;
  iloCount: number;
}
interface TopicRow {
  type: "topic";
  id: string;
  courseId: string;
  title: string;
  archived: boolean;
  iloCount: number;
}
interface ILORow {
  type: "ilo";
  id: string;
  topicId: string;
  courseId: string;
  statement: string;
  code: string;
  bloomLevel: BloomLevel;
  archived: boolean;
}

// Columns definition with expandable grouping
const columns: ColumnDef<HierarchyRow>[] = [
  {
    accessorKey: "type",
    header: "",
    cell: ({ row }) => {
      const icon = row.original.type === "course" ? BookOpen
        : row.original.type === "topic" ? ListChecks
        : Target;
      return <icon className="h-4 w-4 text-muted-foreground" />;
    },
    size: 40,
  },
  {
    accessorKey: "code",
    header: "Code",
    cell: ({ row }) => (
      <div className="font-medium">{row.original.code as string}</div>
    ),
  },
  {
    accessorKey: "title",
    header: "Title / Statement",
    cell: ({ row }) => (
      <div className={row.original.type === "ilo" ? "italic text-muted-foreground" : ""}>
        {row.original.type === "course"
          ? (row.original as CourseRow).title
          : row.original.type === "topic"
          ? (row.original as TopicRow).title
          : (row.original as ILORow).statement}
      </div>
    ),
  },
  {
    accessorKey: "bloomLevel",
    header: "Bloom",
    cell: ({ row }) => {
      if (row.original.type !== "ilo") return null;
      return <Badge variant="secondary">{(row.original as ILORow).bloomLevel}</Badge>;
    },
  },
  {
    accessorKey: "counts",
    header: "ILOs",
    cell: ({ row }) => {
      const count = row.original.type === "course"
        ? (row.original as CourseRow).iloCount
        : row.original.type === "topic"
        ? (row.original as TopicRow).iloCount
        : 0;
      return count > 0 ? <Badge variant="outline">{count}</Badge> : null;
    },
  },
  {
    accessorKey: "archived",
    header: "",
    cell: ({ row }) => row.original.archived && <Badge variant="outline">Archived</Badge>,
  },
];
```

#### 3. ILO Code Generation

Auto-generate ILO codes using pattern `{courseCode}-ILO-{001}` on creation:
- Trigger in Supabase or computed in `createILO` service
- Editable for manual override if needed
- Display prominently in ILO rows

#### 4. Duplicate Detection & Smart Recommendations

**During ILO creation/editing:**
- Query similar existing ILOs (same course OR cross-course) by statement similarity or exact match
- Show a non-blocking alert: “Similar ILO exists: CS101-ILO-003 — 'Apply recursion…'". Offer "reuse" or "create anyway".
- Optional: Use `fuzzysearch` or Levenshtein distance (lightweight) for near-duplicates.

**Duplicate report in CourseManagementHub:**
- Add a new tab "Duplicates" that groups ILOs by statement similarity (exact + fuzzy).
- Use clustering: group by first 5 words, after normalization.
- Allow merging: select two ILOs → "Merge" → reassign references (topics, sessions) to survivor.

#### 5. Visual Hierarchy & Grouping

Use collapsible rows (shadcn `Collapsible` or table grouping):
- Courses as parent rows (bold, thicker border)
- Topics indented below course
- ILOs indented below topic with statement wrap

Alternatively, use `TreeView` component pattern:
```tsx
import { Tree, TreeItem } from "@/components/ui/treeview"; // build from primitives

            <TreeItem value={ilo.id} label={ilo.statement} icon={Target} />

  ))}
</Tree>
```

#### 6. Activity Feed Enhancement

Add contextual details:

#### 7. Bulk Actions

Add checkboxes to rows + bulk toolbar:

## Migration & Backwards Compatibility

1. **Database migration**: Add `code` column to `ilos`; backfill with `COALESCE(code, ...)` generating pattern.
2. **Constraint**: Unique statement per course allows duplicates across courses (likely intended).
3. **Store update**: `types.ts` add fields; `courseStore` fetch extended data via Supabase view or join.
4. **Gradual rollout**: Keep existing tab view as "Legacy" opt-out; new table as default.

---

## Implementation Steps

1. **Schema migration** — add `code` column, uniqueness index, consistency check constraint.
2. **Supabase service** — update `getCourses`, `getTopics`, `getILOs` to return richer data (counts, aggregated).
3. **Store update** — extend types; add computed hierarchies.
4. **New component** — `CourseHierarchyTable` with filters and grouping.
5. **Replace** `CourseManagementHub` content with new table + filters.
6. **Enhance** `ActivityFeedDialog` with richer metadata and entity linking.
7. **Duplicate detection** — optional integration or manual report tab.
8. **Testing** — verify consistency after topic reassignment; ensure constraints catch edge cases.

## Expected Benefits

- Clear visibility of Course → Topic → ILO relationships
- Prevent accidental duplicate ILOs
- Fast filtering by course, Bloom level, archive status
- Scalable to hundreds of ILOs with grouped rendering
- Safer data integrity via DB constraints
- Activity feed provides actionable context
